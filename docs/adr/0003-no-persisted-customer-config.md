# No persisted per-customer field configuration

The assignment's Product Overview mentions extraction based on "customized definitions per customer and document type," which could imply a config system (e.g. a `customer_field_config` table of per-customer aliases/hints feeding the extraction prompt). We chose not to build that. The Adaptability KPI is satisfied by the LLM generalizing across customer phrasing variations — demonstrated by the two customer variants per document type in the sample set — and validated through the accuracy-eval script, not through an admin-configurable mapping layer. Building real per-customer configuration (storage, editing, precedence rules) is a substantially larger feature than this assignment's scope justifies. If a reviewer expects a configurable system, that's the gap to point to.
