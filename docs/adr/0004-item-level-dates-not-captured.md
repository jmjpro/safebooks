# Item-level Start/End dates not captured

The assignment spec's Item field list (Product name, Quantity, Price, Total Amount) has no date fields, and neither do CONTEXT.md's Item definition or the `ExtractedItem`/`so_items`/`po_items` shape. All four sample documents' items tables carry a Start Date / End Date column per row nonetheless — ACME's and CloudShield's Order Forms split subscriptions into per-contract-year line items, and both BrightOps' and NovaFleet's Purchase Orders carry the same columns per line item — but that spread is always redundant with the document-level `startDate`/`endDate` Structured Fields (a year-1/year-2/year-3 split of the same overall contract term, or the same term repeated per line). We chose not to capture item-level dates, matching the assignment brief and CONTEXT.md rather than the raw table shape. If a real document arrives where an item's date range diverges from the document-level term (e.g. a mid-contract add-on with its own start date), that's the signal to add `start_date`/`end_date` columns to `so_items`/`po_items` and the corresponding fields to `ExtractedItem`.
